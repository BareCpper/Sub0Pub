## Method notes

- **Same work everywhere.** Every receiver increments a counter in an out-of-line `receive()`, and every publish entry
  point is out of line. An empty out-of-line receiver would let the optimiser delete a non-virtual call (a first run
  of this comparison showed static wiring at 1 instr/op for that reason), while a virtual call can never be deleted.
- **v2 rows.**
  - "v2 default" is the header with no policy macro: Direct dispatch, no publish context, no `filter()`, no lock.
  - "debug checks" adds the checks a debug build enables by default: `SUB0PUB_REENTRANT_CHECK` and `SUB0PUB_THREAD_CHECK`.
  - "Full" opts every type into snapshot dispatch, `cancel()` and `filter()`, the earlier v2 default.
  - "v2 before Phase 2" is the header at `9b9d759`, before the per-type broker replaced it (`--extra-ref`).
  - The "v2 config" rows reach the same configurations per type and measure the same, except publishing to no
    subscribers, which differs with how the benchmark passes the message: `cmp_sub0pub.cpp`'s `send(int)` takes it by
    value, which makes gcc save registers before the empty-table check. v1.0 is measured with the same `send(int)`.
- **`filter()` is a real virtual call** wherever the configuration has one: each such build also contains a
  subscriber that overrides `filter()`, as `tests/bench/bench_core.cpp` does. The re-check after `filter()` added by
  the 2026-09 review costs 2 instructions per delivered subscriber (Full, 8 subscribers: 274 without it, 290 with it).
- **ThreadSafe** subscribers call `trySubscribe()` after construction (the v2 activation contract) outside the
  measured loop; create + destroy includes it.
- **v1.0 header.** Read from the tag with `git show`. It uses `std::runtime_error` without including `<stdexcept>`,
  so the benchmark includes it first; nothing else is changed. Only API common to v1.0 and v2 is used.
- **n/a** means the implementation has no such operation: the default has neither `filter()` nor `cancel()` (both
  opt-in); static wiring has no `filter()` and no per-subscriber lifetime (DynamicPort's add + remove is shown as
  create + destroy).
- **gcc, Full = Full with StaticContext.** In a non-PIE executable gcc's thread-local access is a single
  segment-relative load, as cheap as a global; clang's differs by 4 instructions.
- Footprint uses the flags of `tests/footprint/measure_footprint.py` and reproduces its numbers for the shared rows.
