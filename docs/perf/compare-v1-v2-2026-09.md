## Method notes

- **Same work everywhere.** Every receiver increments a counter in an out-of-line `receive()`, and every publish entry
  point is out of line. An empty out-of-line receiver would let the optimiser delete a non-virtual call (a first run
  of this comparison showed static wiring at 1 instr/op for that reason), while a virtual call can never be deleted.
- **`filter()` is a real virtual call** wherever the configuration has one: each build also contains a subscriber that
  overrides `filter()`, as `tests/bench/bench_core.cpp` does. The design prototype's own `bench_sub0x.cpp` has no
  override, so gcc devirtualises `filter()` there; that is why its Default row (73 / 220 for 1 / 8 subscribers) is
  lower than here (80 / 290).
- **Cost of the `filter()` re-check** added by the 2026-09 review (`kit::deliverAt`): with a real `filter()` it is
  2 instructions per delivered subscriber on gcc and clang (Default, 8 subscribers: 274 without it, 290 with it).
  Without a filter, or with `filter()` devirtualised, it costs nothing.
- **v2 rows** measure the current header. "v2 Snapshot (default)" and "v2 config Default" are the same configuration
  reached two ways (the macros, and an explicit per-type default) and measure identically. "v2 before Phase 2" is the
  header at `9b9d759`, before the per-type broker replaced it (`--extra-ref`).
- **ThreadSafe** subscribers call `trySubscribe()` after construction (the v2 activation contract) outside the
  measured loop; create + destroy includes it.
- **v1.0 header.** Read from the tag with `git show`. It uses `std::runtime_error` without including `<stdexcept>`,
  so the benchmark includes it first; nothing else is changed. Only API common to v1.0 and v2 is used.
- **n/a** means the implementation has no such operation: static wiring has no `filter()` and no per-subscriber
  lifetime (DynamicPort's add + remove is shown as create + destroy); Lean has neither filter nor `cancel()`.
- **gcc, Default = StaticContext.** In a non-PIE executable gcc's thread-local access is a single segment-relative
  load, as cheap as a global; clang's differs by 4 instructions.
- Footprint uses the flags of `tests/footprint/measure_footprint.py` and reproduces its numbers for the shared rows.
